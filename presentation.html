4Deterministic

Non-deterministic

  • Side effects
  • Hidden inputs
  • Potential for different results
  • Different results on different machines
vs.

Deterministic

  • Pure functions
  • Explicit inputs
  • Always same input, same output
  • Same results on every machine

Live Demo

Non-deterministic vs. Deterministic

4nixpkgs

nixpkgs

  • Package recipes
  • A git repository
  • Each commit is a snapshot
+

configuration.nix

  • Describes your system
  • Uses nixpkgs from your channel
  • A channel is a moving pointer
  1. Install NixOS
  2. Automatically subscribes to a channel (hidden input)
  3. Packages come from that channel's nixpkgs snapshot
  4. The channel is a moving pointer: update it and you get a newer snapshot
  5. Non-deterministic: the same config doesn't run the same on every machine, it depends on the channel each machine is subscribed to

4Flakes

flake.nix

  • Declares the inputs
  • nixpkgs, and anything else
+

flake.lock

  • Pins each input to an exact commit
  • Builds use the lock, not the channel
  • Replaces the default channel subscription(s)
  • Inputs are declared in flake.nix: hidden input becomes explicit input
  • flake.lock pins the exact commit (sha) of each input
  • Builds use the lock, not the machine's channels
